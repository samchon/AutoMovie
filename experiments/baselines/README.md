# 실험 기준선

한 실험이 끝나고 그 샌드박스가 사라진 뒤에도 남는 기록이 여기 산다.

샌드박스는 `experimental/` 아래에 살고 gitignore된다. 그래서 그 안에서 잰 것은 샌드박스와 함께 사라지고, **저장소에 tracked로 옮겨 적은 것만 남는다.** 이 디렉터리가 그 자리다. 이 기록은 실행 지침이 아니므로 `.agents/skills/` 밖에 둔다. 실행 절차와 판정 스키마는 [experiment skill의 records 문서](../../.agents/skills/experiment/records.md)가 소유한다.

파일 하나가 실험 하나다.

```
experiments/baselines/<sandbox-name>.md
```

## 왜 형식을 고정하는가

여러 실험이 동시에 돌 때 각자 자기 형식을 발명하면 **그 기록들이 서로 다른 것을 재게 된다.** 나란히 놓고 비교할 수 없고, 비교할 수 없는 기준선은 기준선이 아니다.

같은 이유로 baseline마다 일회성 측정 스크립트를 새로 만들지 않는다. Campaign은 첫 production 전에 frozen observation plan과 검증된 공통 instrument를 마련하고 모든 run에 같은 revision을 사용한다. 공통 instrument가 다루지 않는 값을 손으로 재면 그 절차, 시점과 오차 경계를 기록하며 다른 run의 자동 수치와 같은 measurement로 합치지 않는다.

## 무엇을 남기는가

문서 하나에 아래 다섯 절을 이 순서로 둔다. **없는 값은 비우지 않고 `unverified` 또는 `n/a`와 그 이유를 적는다.** 빈칸은 측정하지 않은 것과 0을 구별하지 못한다.

### 1. 정체

샌드박스 이름, 담당 이슈, 실행 시점의 head sha, 저작 세션의 종류와 재개 식별자.

### 2. 규모

컴파일된 산출물에서 주체 총수, 프로토타입, 건축 element, 공간, 인스턴스 집합, 모델과 부품을 잰다.

규모 비교 기준 하나를 적어둔다. `#1939` 사이클의 검증 픽스처가 주체 4,003 / 프로토타입 199 / element 3,474 / 공간 15 / 인스턴스 집합 8 / 모델 197 / 부품 398이었다. 이 참고값은 실험 조건을 공유한 대조군이나 반복 실행이 아니며 인과 주장을 뒷받침하지 않는다.

### 3. 비용

벽시계로 샌드박스 생성(pack 포함), 첫 컴파일, 첫 렌더, 방 스케줄, 텍스처 축척, 주체 관찰 1건과 전체 프로토타입 스윕 시간을 잰다.

**측정 시점의 머신 부하를 함께 적는다.** 이 저장소의 실험은 다른 캠페인과 머신을 공유할 때가 있고, 부하를 적지 않은 벽시계는 비교가 불가능하다. 한 사이클에서 자유 카메라 프레임을 367 ms로 재고 "이건 상한이지 깨끗한 값이 아니다"라고 단서를 단 적이 있는데, 그 단서가 그 수치를 살렸다.

### 4. 도달

저작 에이전트가 실제로 무엇을 몰았는가. 쓴 도구와 각각의 성패, 막힌 지점과 그때 제품이 준 진단, 그리고 **저작자가 못 한 것과 제품이 길을 안 준 것을 반드시 나누어** 적는다.

이 절이 실험의 본체다. 나머지 넷은 이 절을 읽을 수 있게 하는 맥락이다.

### 5. 판정

제품이 실제로 감당한 것, 거절한 것, 그리고 그 거절이 정당했는지. 결함은 **재현 절차와 함께**. 확인하지 못한 주장은 전부 `unverified`.

## 규율

- **수치에는 언제 잰 것인지를 붙인다.** 센 주장은 드리프트하고, head가 없으면 낡았다는 사실조차 보이지 않는다.
- **자격증명은 값도 키 이름도 남기지 않는다.**
- 산출한 이미지 경로를 남긴다. 사람이 직접 본다.

이 형식은 실험이 늘면서 다듬어질 수 있다. 다만 **진행 중인 실험들이 같은 형식을 쓰는 것**이 형식 자체보다 중요하다.
