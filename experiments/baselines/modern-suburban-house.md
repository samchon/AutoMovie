# modern-suburban-house

**진행 중인 실험의 중간 기준선이다.** 이 사이클에서 드라이버가 세션 한도로 한 번
교대했고, 저작 세션은 살아 있다. 실험이 끝날 때까지 기다리지 않고 확인된 값부터
착지시킨다. 아직 재지 못한 값은 비우지 않고 `unverified` 또는 `n/a`와 그 이유를 적는다.

마지막 갱신: 2026-08-18 12:38, head `31922bd1` (`master`), 턴 3 진행 중.

**이 문서는 MCP 도구를 이름으로 적지 않는다.** 이 실행이 사는 축이 **발견 가능성**이고,
샌드박스가 저장소 안에 살아 Codex가 git 루트의 `.agents/skills/`를 주입하므로 이
경로는 저작 세션이 읽을 수 있다. 이름을 적으면 그 축이 그 순간 죽는다. 이 세션의
제품 표면 호출이 0건이라 사실 손실도 없다.

## 4. 도달

이 절이 실험의 본체다. **저작자가 못 한 것과 제품이 길을 주지 않은 것을 나눈다.**

### 제품 MCP 표면 호출은 0건. 그러나 "거절"이 아니라 "시도 없음"이다

| 측정 | 값 |
| --- | --- |
| 제품 서버 이름의 rollout 등장 | **0회** (19.8 MB 전체 리터럴 grep) |
| 전역 등록 `node_repl` 등장 | 142회, invocation 레코드 57건 |
| `user cancelled MCP tool call` | **0건** |
| MCP 승인 거절 | **0건** (`denied` 8건은 전부 MCP가 아니다) |
| 서버 프로세스 생존 | **살아 있었다** — 턴 3에서 codex 루트의 직계 자식으로 실측 |

**따라서 이 0은 죽은 채널이 아니다.** 형제 샌드박스는 *시도 N, 거절 N*이었고
여기는 **시도 0**이다. 등록·승인 규칙은 거절을 설명하지만 **표면에 아예 손을 뻗지
않은 세션은 설명하지 못한다.** 둘은 다른 관측이고 집계에서 같아 보인다.

**MCP 결과는 반드시 `invocation.server`별로 센다.** 총계로 세면 전역 등록 서버의
성공이 제품 표면의 실패를 가린다. 드라이버 둘이 같은 방식으로 자기 총계를 오독했고,
"형제가 재현하지 못했다"던 예외는 **애초에 존재하지 않았다.**

**운영 규칙:** 서버를 호출 단위로 등록하면 **반드시** `-c approvals_reviewer="auto_review"`.
호출 단위 등록 서버는 승인을 요구하고 전역 등록 서버는 요구하지 않으며,
`approval_policy: never` + 기본 `approvals_reviewer: user`가 그 요구를 자동 거절한다.

**0을 세기 전에 채널 생존을 먼저 세운다.** 싼 방법: **MCP 서버 프로세스는 codex
프로세스의 자식**이므로, 0이 관측된 그 시점에 그것이 있었는지가 죽은 채널과 조용한
에이전트를 가른다.

### 세션이 가이드 지식에 도달한 경로 — 도구가 아니라 소스와 라이브러리

세션은 제품 패키지의 가이드 상수 소스를 **직접 읽어** 본문을 얻었고, 표면을
**도구가 아니라 API로** 취급했다(라이브러리 import 시도). 즉 표면을 **못 찾은 것이
아니라 찾아서 다르게 썼다.**

**도구 이름은 드라이버가 흘린 것이 아니다 — 제품이 자기 표면에 싣고 판다.**
작업 루트의 `README.md`, 프로젝트 자기 스크립트들, 그리고 `node_modules/@automovie`
아래 다수가 이름을 배송한다. **드라이버가 이름을 쓰지 않는 것만으로는 무지를
강제할 수 없다.** 강제할 수 없는 것을 주장하지 말고 **셀 순서로 통제할 수 있는 것**을
주장한다. 이 실행의 드라이버 유출은 **0건**이다(모든 턴 메시지를 정규식으로 검사).

### 브리프 자신의 모순 — 프로덕션의 결함이 아니다

**`dog-leg` 한정어만 어긋난다.**

위에서 S1을 다시 짓게 만든다). **귀속은 브리프이지 프로덕션이 아니다.**

## 5. 판정

### 제품이 감당한 것

- **진단의 질과 정직한 거절.** `building:report`가 기하 0에서 "그릴 것도 셀 것도
  없다"고 exit 0으로 거절했고, 기하가 생긴 뒤에는 **자기가 못 한 것 50건을 스스로
  열거**한다. `texture:scale`도 "아무것도 측정되지 않았으며 이 실행은 리뷰가
  아니다"라고 먼저 말한다. **알려진 0에서 정직하게 거절하는 것이 나중의 비-0
  출력을 믿을 수 있게 만든다.**
- **`capture:doctor`가 시정 명령을 이름으로 준다.** 설치 전 exit 1에서
  "`capture:install`을 돌린 뒤 다시 `capture:doctor`"를 그대로 말한다.
- **결정론.** `angle:swiftshader`는 조용한 폴백이 아니라 제품이 **결정론을 위해
  요청한** 백엔드이고, doctor가 renderer 문자열과 실행 파일 digest를 영수증으로 낸다.
  다만 **결정론은 이 실행이 측정하지 못했다** — 아래 「프레임 해시는 결정론의
  증거가 아니다」를 볼 것.
- **경계가 약속이 아니라 강제된다.** 세션이 저장소 루트에 git 브랜치를 만들려다
  권한 오류로 거절당했다. 샌드박스만 쓰기 가능하다.

### 결함 (재현 절차 포함)

**D1 — 죽은 프로세스가 남긴 commit lock이 프로젝트를 영구 봉쇄한다. → `#1994` 발행됨**

재현: 저작 세션을 턴 도중 죽인다. 그 프로세스가 잡고 있던 lock 3개가 남는다 —
`<home>/.automovie-root-locks/production-{id,path}-<sha256>.lock` 둘과
`automovie/productions/<id>/revision.lock` 하나. 이후 **모든** 프로젝트 명령이
`the project commit lock is held by another session`으로 exit 1.

- lock 토큰은 `${process.pid}.${nonce}.${timestamp}`로 **소유자 PID를 담고 있다.**
  실측된 소유자 PID는 **부재**했고, 그 시각대에 생성된 프로세스가 하나도 없어
  PID 재사용 후보도 없었다.
- **제품은 그 PID를 한 번도 조회하지 않는다.** 복구 경로가 **사람**이다 —
  에이전트가 저작을 몬다는 것이 제품의 테제인데도.
- `commitLock.ts`의 JSDoc이 설계 근거를 스스로 적는다(mtime 회수기는 소유자의 사망을
  증명할 수 없고, stat-then-rename은 새 소유자의 파일을 옮길 수 있다). **근거는
  건전하다.** 결함은 근거가 아니라 **자동 회수 경로의 부재**다.
- **naive fix 경고:** 기록된 id의 생존만 확인하는 것은 **그 자체로 안전하지 않다.**
  이 캠페인이 PID 재사용을 실측했고 재사용자가 형제 캠페인일 개연성이 있다.
- **소유를 가정하지 않고 증명하는 방법(이 실행이 쓴 것):** `rootNamespaceLock.ts`의
  좌표 유도를 읽고 digest를 **재계산**해 파일명과 대조한다. 좌표는
  `production-path`가 `root` + productionId를, `production-id`가 device+inode+productionId를
  sha256으로 접은 것이다. **좌표가 root에 묶여 있으므로 전역 디렉터리를 쓰면서도
  형제 캠페인과 충돌하지 않는다** — 같은 이름의 샌드박스가 다른 저장소에 실재하므로
  반드시 확인해야 했던 축이고, 확인 결과 **충돌 없음**이다.

**D2 — 모듈 스코프 `os.userInfo()`가 패키지 전체 import를 가져간다. → `#1992`**

`rootNamespaceLock.ts`가 모듈 스코프에서 `os.userInfo()`를 부르고 배럴이 그 모듈을
re-export한다. 그 syscall이 한 번 실패하면 **패키지 전체 import가 실패한다** —
root namespace lock을 전혀 쓰지 않는 소비자까지 함께. 이 환경에서 그것이
**간헐적으로 13회** 실패했고(`uv_os_get_passwd returned ENOMEM`), **같은 샌드박스가
다른 시점에는 같은 패키지를 정상 import했다**(revision 37까지 컴파일 성공).
**따라서 결함은 "샌드박스가 막는다"가 아니라 "폭발 반경과 취약성"이다.**
그 시점 물리 메모리는 11 GB 넘게 비어 있었다 — `ENOMEM`이라는 문자열이 원인을 오도한다.
수정(lazy `coordinationRoot()`)이 `#1995`로 진행 중.

**D3 — `preview`는 read-only가 아니다.** 관측만 했는데 revision이 **40 → 41**로 올랐다.
경로가 `preview → freshnessDiagnostic → oracle → compiler.lint → confirmInputSnapshot
→ commitFiles`라 스냅샷을 커밋한다. **드라이버가 이것을 관측 수단으로 쓰므로 중요하다** —
"내가 돌린 것이 아무것도 변형하지 않았다"는 프레임 바이트에는 맞고 revision에는 틀리다.

**D4 — `capture:doctor`가 갓 설치된 브라우저에서 1회 거짓 실패할 수 있다.**
ancient에서 재현됐고 여기서는 나오지 않았다. 제품 메시지가 재실행을 지시하므로 치명적이지 않다.

### 프레임 해시는 결정론의 증거가 아니다 — 철회

**프레임은 content-addressed다.** 경로가
`shot-<id>/<targetFingerprint>/<rendererIdentity>/preview/frame_*.png`이라
재렌더는 기존 경로를 덮지 않고 **새 digest 디렉터리를 만든다.** 따라서 "이전 라운드
프레임 중 N장이 바뀌었다"는 **주소 체계가 보장하는 0**이다. **실패할 수 없는 비교는
증거가 아니다.**

실측: `house-front`가 target fingerprint 디렉터리 **4개**, `room-entry`가 **3개**를
갖고 있고, **모든 (target, renderer) 쌍이 정확히 한 번씩만** 나타난다. 즉 **같은
fingerprint를 두 번 렌더한 적이 없으므로 결정론 증거는 0건이다.**
서로 **다른** fingerprint 둘이 바이트 동일한 픽셀을 낸 것은 결정론이 아니라
**fingerprint가 픽셀에 반영되지 않는 무언가에 민감하다**는 관측이다.
프레임 해시는 **회귀 트립와이어**로만 쓴다.

### 대체 계측기 — propagation shape

라운드 사이에 **무엇이 무엇으로 번졌는가**를 센다. 실패할 수 있는 주장이다.
앵커는 **턴 시작 시각**이고, 그 이후 mtime을 가진 파일이 그 턴의 전파다(열린 핸들을
가진 rollout과 달리 닫힌 산출물의 mtime은 신뢰할 수 있다).

턴 3 예비 판독(진행 중이라 번져 있음): `automovie/design` **0/25**,
`generated` **23/67**(shot 20개 전부 + compile/film-edit/film-timeline),
`reports` **7/7**, `src` **7/59**. 새 render digest 디렉터리는 드라이버가 지목한
**바로 그 세 shot**에만 생겼다.

**이 프로덕션의 shape는 형제와 다르다.** 형제는 design 1개 변경 → 222 중 22 변경,
움직인 shot은 마주보는 둘뿐이었다. **여기는 design이 0/25인데 shot 20개가 전부
다시 쓰였다** — 소스 편집이 design 레이어를 거치지 않고 컴파일 산출물로 바로 번지며,
**기하 한 곳의 변경이 모든 shot 산출물을 다시 쓴다.**

### 계측 방법론 — 이 실행이 산 것

**계측기 함정은 전부 "그럴듯한 결과"로 실패한다.** 터지지 않고 말이 되는 답을 주기
때문에 라운드를 넘어 살아남는다. 이 캠페인이 실측한 여섯:

1. **조회가 자기를 잡는다** — 식별 쿼리의 커맨드라인에 검색 문자열이 들어 있다. `$PID` 명시 제외.
2. **괄호 없는 `-and`/`-or`** — 무관한 프로세스가 통과한다.
3. **키 타입 불일치** — `ParentProcessId`는 `UInt32`인데 `Int32`로 조회하면 조용히
   "자식 없음"을 낸다. **이것은 "턴이 끝났다"와 구별되지 않는다.**
4. **큐 슬라이싱** — `$queue[1..0]`이 같은 원소를 다시 넣어 무한 루프가 되고
   **평범한 느림으로 보인다.**
5. **하니스의 거짓 완료 알림** — 태스크 래퍼가 회수되며 완료를 보고하는데 세션은
   살아 있다. 실측: 그 시점 rollout이 1.2 MB 더 자랐다.
6. **프레임 해시 비교가 실패할 수 없다** — content-addressing이 0을 보장한다(위).
7. **정규식이 자기를 잡는다** — 문서 텍스트의 도구 심볼 **플레이스홀더**를 실제
   호출로 셌다. 리터럴 grep으로만 걸렸다.

**턴 경계 판정 규칙 (이 실행이 확정):**
1차 신호는 **내가 띄운 메인 `codex.exe`의 종료**, 교차 확인은 **rollout 크기**
(mtime 아님 — 이 파일시스템에서 스탬프가 고정된 채 파일이 자란다), 셋째는 디스크.
**셋이 일치할 때만 믿는다.** 뿌리는 wrapper가 아니라 그 아래 메인 `codex.exe`에 두고,
**PID와 생성 시각을 함께** 고정한다 — PID는 재사용되고 재사용자가 형제 캠페인일 수 있다.

**스크래치패드는 샌드박스 이름으로 네임스페이스한다.** 드라이버 넷이 하나를 공유하므로
`turn2.log` 같은 일반 이름은 구조적 충돌이다. 실제로 한 드라이버의 로그가 덮여
**남의 턴에서 거짓 경계가 발화할 뻔했다.** 경계는 내가 이름 붙인 로그가 아니라
**세션 UUID를 파일명에 단 rollout**에서 잡는다.

### 계측기 함정 — 새 유형: **입력을 들어오는 길에 무력화한다**

앞선 것들은 전부 **받은 적 없는 입력에 대해 자신 있게 답했다**(빈 목록이 IDENTICAL,
잘린 파이프가 exit 255, 빈 패턴이 전부 매치). **이것은 다른 방향이다 — 검사 대상
메커니즘을 스스로 꺼놓고 그 꺼진 결과를 데이터로 읽는다.**

실측 (드라이버 자신이 저지름). `.mcp.json`의 `${CLAUDE_PROJECT_DIR:-.}`가 확장되지
않는다고 주장하며 근거로 이것을 썼다:

```sh
ls '${CLAUDE_PROJECT_DIR:-.}/node_modules/tsx/dist/cli.mjs'   # 작은따옴표
```

**작은따옴표가 bash 확장을 막는다.** 그래서 이 명령이 보일 수 있는 것은 "리터럴
문자열은 유효한 경로가 아니다"뿐이고 그것은 자명하게 참이다. 같은 셸, 변수 unset:

| 명령 | 결과 |
| --- | --- |
| `ls '${CLAUDE_PROJECT_DIR:-.}/package.json'` | `No such file` ← 확장 차단됨 |
| `ls "${CLAUDE_PROJECT_DIR:-.}/package.json"` | `./package.json` ← **기본값 정상 동작** |

**주장은 철회됐다.** 헤드리스 세션은 두 형태 모두 절대 경로로 해석하고, `claude -p`가
스스로 `CLAUDE_PROJECT_DIR`를 설정한다. 스캐폴드 `.mcp.json`은 깨지지 않았다.

**일반화:** 어떤 메커니즘을 시험할 때 **그 메커니즘을 끄는 형태로 시험하지 않았는지**
먼저 묻는다. 인용부호, `--dry-run`, 모킹, 비활성화 플래그가 전부 이 자리에 온다.
**꺼진 기계는 언제나 "동작하지 않는다"고 답한다.**

### 살아남은 것 — `claude mcp list`는 게이트가 아니라 진단이다

양방향으로 틀린다: 이 샌드박스에서 **정상 동작하는 구성에 `Failed to connect`**,
다른 프로젝트에서 **바로 다음 세션에 정상 기동한 서버 셋에 `Pending approval`**.
**이유가 함정이다 — 헬스 체크는 세션이 쓸 조건과 다른 조건(다른 cwd, `CLAUDE_PROJECT_DIR`
주입 없음)에서 띄운 _다른 프로세스_ 에 대해 판정한다.**

**게이트는 세션 자신의 서버별 도구 호출 수이고, 그 다음이 혈통이다** —
MCP 서버가 그 세션 루트의 직계 자식인지. 그것이 *이* 세션에 대한 증거다.
