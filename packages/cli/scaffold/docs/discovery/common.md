# Production-Specific Contract Discovery

Work-wide and cross-layer outcomes that every authored H2 population revisits. Layer-local requirements belong in that layer's discovery file, and conditions shared only by film prose belong in `films.md`.

## Shared and local boundary {#shared-local-boundary}

Determine which recurring production-wide or cross-layer conditions remain unowned after applying the shared principles and obligations. Search the production's directives, identity, promise, subject, sources, assets, dependencies, risks, and observed failures without treating those inputs as a checklist. An independent result has its own applicability, intended effect, and observable failure boundary; a concrete answer to an existing shared question is not a new rule.

A positive acknowledgement identifies each retained result. If none exists, one population-wide exclusion names the concrete inputs and risks examined and the shared owners that fully cover them. A label, aspiration, copied item, or audit assertion is not a result.

Review question: which production-specific condition remains independently applicable after the shared graph answers its complete reusable questions?

Sources: [NASA on eliciting and validating requirements from stakeholder needs and system context](https://www.nasa.gov/reference/4-1-stakeholder-expectations-definition/); [ISO/IEC/IEEE 29148:2018 on requirements quality](https://www.iso.org/standard/72089.html)

## Canonical realization {#canonical-realization}

Give every retained result one semantic owner, an observable stage-appropriate realization, and any additive claim its independent evidence behavior requires. Do not leave an adopted rule only in `.wiki`, a brief, an issue, or prose instructions, and do not create an empty target.

A positive acknowledgement identifies the current owner and stage-appropriate realization, plus any independent target and claim the result requires. An exclusion is valid only when the boundary search found no independent result, not when implementation is deferred.

Review question: where is each retained result owned, realized, and wired so a later layer cannot silently replace or omit it?

Sources: [NASA on requirements verification matrices](https://www.nasa.gov/reference/system-engineering-handbook-appendix/); [W3C PROV-O on responsibility and derivation](https://www.w3.org/TR/prov-o/)
