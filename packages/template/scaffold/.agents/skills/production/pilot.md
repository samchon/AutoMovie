# Vertical-slice pilot

Prove one smallest useful production slice through its last owned realization layer before expanding the population. The pilot narrows population, never contract strength, canon, or the production promise.

Use this mode when later realization is likely to expose an expensive upstream defect and the selected shape has a truthful slice. A film can pilot the events realized by its first delivery group through treatments, scripts, and screenplays. A fresh library can pilot one design owner through its matching source branch before adding sibling owners. A brief already is one bounded delivery, shot, and observation hierarchy; record that no smaller slice would test a distinct downstream boundary instead of manufacturing one.

## Choose the slice

Keep settings and research scoped to the complete declared production. Complete their applicable discovery, authored contract, evidence, and review work before the pilot begins. A pilot may reveal a settings defect, but it may not evade one by narrowing canon to the convenient facts used by the slice.

For a film, choose one exact first delivery-group directory and declare:

```ts
populationScope: {
  mode: "first-pilot",
  partitionGroup: "001-exact-lower-kebab-name",
}
```

Treatments are a flat ordered event population and own no delivery directory. During the pilot, author only the treatment events that the selected group realizes. Scripts design the delivery partition, and screenplays inherit that exact group. An uncited treatment event means the group does not realize the declared slice; repair the treatment selection or delivery boundary instead of excluding the event. This rule constrains which events exist yet, not how many script or screenplay units they become and not how much body each treatment receives.

For a fresh library, declare `populationScope: { mode: "first-pilot" }`, choose one independently reviewable model, building level or zone, space, material, instance, motion, or system owner, and take the real design/source branch that realizes it through review. Author no sibling owner during the pilot. The existing graph already treats each design/source branch independently, so do not invent a film group or weaken the branch's source-export obligations. If the branch already contains an out-of-slice owner or export that the graph cannot select independently, the slice is not truthful and the authoring procedure refuses pilot entry; use the complete branch process. Raw globs, file-per-owner rewrites, and temporary file moves are not a truthful selector.

Preserve any pre-existing out-of-scope artifact unchanged. An artifact the declared scope does not select is inactive source material, not pilot evidence, and receives no opportunistic cleanup or rewrite.

## Run the full-strength ladder

Only the population is smaller. Every shared and production-local principle, obligation, discovery duty, upstream duty, foundation, lineage or coverage relation, stage gate, review requirement, and negative probe that binds a realized host still binds it at full strength. A production-local film claim passes `createAutoMoviePopulationFiles` into the applicable production principle or obligation claim factory and sets `inapplicable: true` only when its target genuinely requires the complete population. Never make a duty inapplicable when one realized host owes it regardless of population size. A library claim keeps the branch's ordinary complete design/source files because no truthful owner selector exists.

Advance one layer at a time through `disabled -> draft -> evidence -> review`. Do not open a child until its direct parent is reviewed.

For a film:

1. take the flat pilot treatment population through review;
2. take the selected script delivery group through review; and
3. take the matching screenplay delivery group through review.

For a library, take the selected design owner through review, then its matching source population through review and the neutral observation set that branch requires. If the pilot needs a second design branch to be truthful, that branch is part of the slice and owes the same complete process; a convenience dependency is not an exclusion.

Coverage is the verticality test. Every pilot treatment event must be realized by the selected script group, every script unit must identify the treatment work it realizes, and every screenplay unit must preserve its exact script identity while covering the treatment events it renders. A library source must cite the selected design owner with the branch's normal cardinality. Material outside those relations is not evidence that the slice is complete.

## Pass the pilot

After the last pilot layer enters review, reread the entire slice as one production. Rerun applicable discovery and inspect canon, allocation, partition, lineage, upstream sufficiency, execution, source ownership, observation coverage, scale, and every production-local contract. Repair each defect at its earliest owner, propagate the consequence through the whole slice, renew every affected review, and rerun the source and evidence gates.

The pilot passes only after two consecutive complete vertical reviews find nothing and make no content or evidence edit. A clean lint run does not replace either literal review.

## Return to the complete production

After the pilot passes, make one explicit mode-transition commit that changes `populationScope` to `{ mode: "complete-production-reset" }`, moves every pilot-authored layer or design/source branch together to `draft`, and leaves the reviewed pilot artifacts in place as editable source material. This is the only permitted stage reset.

The reset state selects the complete population but keeps retained pilot annotations inactive while the full first version is rebuilt. Those annotations may remain in the retained files during this state; they do not pay any complete-production claim, do not certify unchanged content, and must be reread and renewed when the rebuilt layer returns to evidence and review. New or revised body receives no evidence tag while its branch is draft.

The transition is invalid if a pilot diagnostic or review finding remains, if only part of the pilot ladder resets, if an out-of-scope artifact was discarded to make the transition pass, or if a complete-population claim is enabled against the retained slice as though it already covered the work.

Rebuild from the earliest owner, not from the item after the pilot:

- a film redesigns and authors the complete flat treatment sequence with the pilot events retained, moved, split, merged, or replaced as the complete work requires; only after reviewed treatments exist does it design the complete script delivery partition, and only after reviewed scripts exist does it rebuild screenplays;
- a library rereads the complete intended asset scope, reruns discovery, and designs every required owner before completing each source branch. The pilot owner remains a proposal tested in isolation, not a privileged template siblings must copy.

Pilot evidence and reviews never satisfy the expanded population. When every complete layer and branch has passed its ordinary evidence and review gates, change the scope to `{ mode: "complete-production" }` in one final transition commit. No reset exception remains after that change.

## Relationship to the scratch trial

A disposable `.wiki` trial remains useful before the compiler-visible pilot. It is cheaper and can reveal an obviously missing space, subject, exchange, interface, or observation before any governed host exists. It proves nothing: the graph never reads it, no stage applies to it, and it cannot satisfy either clean vertical review.

Use the scratch trial as an optional preflight, then run the pilot when the cost of exercising the real contracts and compiler is justified. Promote every retained decision into its canonical owner before the pilot cites or relies on it.
