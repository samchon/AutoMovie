# Shared upstream revision duties

`@automovie/template` publishes one upstream file per inheriting authored population under `docs/upstream/design`, `docs/upstream/story`, or `docs/upstream/delivery`. Each asks the same question in its own direction: what did authoring this unit prove wrong in the units it inherits, and what was repaired there? Settings and research inherit no authored production unit and never select this family.

## Why it is its own family

Discovery asks what this production needs that no shared target names. Upstream revision asks what the production already got wrong. Principles test the current unit, and obligations distribute roles across a population. Upstream instead requires the current unit to examine its actual parents and record either their repair or their concrete sufficiency. A silent pass is not a tested one.

Parent differentiation remains separate. It asks what layer-owned decision the child added beyond its parents and permits no exclusion. Upstream asks whether those parents were adequate and permits a truthful negative when they were. One unit can pass either and fail the other.

## Form

- One shared file serves one inheriting population, with one H1 and one fixed-anchor H2. The question is asked once per unit, not once per defect kind.
- The target states what this population's own work can expose in its parents: layout tests dimensions and interfaces, material binding tests stable surfaces, motion tests writable domains and limits, narrative realization tests whether its parent survives staging, and source implementation tests whether reviewed design is executable without invention.
- Name target and finding together. "Revised settings" or "implemented design" records nothing; identify the parent target, what this unit exposed, and the repair made there.
- Never supply a missing capability, limit, participant, refusal, interface, dimension, source basis, or acceptance condition in the child. Return to the earliest owner, repair it, propagate the result, and then resume the child.

## Coverage and exclusion

Upstream is an exclusion-permitted checklist over every selected inheriting authored unit or source export. Each host answers because the lineage runs unit to unit. A file-level or population-level answer would let one child speak for siblings with different parents.

A positive `@evidence` names every parent target repaired and what this child exposed. A negative `@evidenceExclude` names the actual parents, concrete facts and decisions examined, and why they were sufficient for this child. Refusing the negative would force sound parents to acquire fictional defects. "No change needed", an audit assertion, or one sentence repeated across hosts is unanswered.

A child with no actual parent cannot truthfully answer either branch and is refused. Do not fabricate an exclusion, infer a parent from directory order, or cite the upstream target as if it were the parent. Fix the lineage first.

## Authoring pass

Run the pass immediately after one inheriting unit reaches a complete draft and before staging its other evidence:

1. Resolve every actual parent through the unit's lineage citations and read those parent units in full.
2. Exercise the child at its layer's concrete boundary: derive, lay out, bind, populate, move, couple, stage, realize, implement, assemble, or observe it as applicable.
3. For each mismatch, identify the earliest parent that owns the missing or contradictory decision, repair it there, and propagate the repair through every affected descendant.
4. Rerun the child boundary test. Record a positive answer when a repair occurred; otherwise record the concrete parent decisions that the completed test found sufficient.
5. Renew every review invalidated by the parent change. A downstream review cannot remain current merely because its prose still parses.

When another agent owns the parent, stop the dependent unit, send the exact target, finding, earliest owner, affected descendants, and required recheck, and resume only after that repair is integrated. Discovery and research remain separate decisions: upstream may reveal a missing reusable rule or missing current fact, but it routes those findings to their owners instead of absorbing their workflows.
