# Recording authored work

Commit one coherent authored unit at a time. After each complete creation or material revision, stage exactly the paths that unit owns, run `git diff --check` on the staged content, inspect the staged list, and refuse unrelated or generated bytes. A stage-transition commit records the complete coherent snapshot required by evidence staging; a progress commit stays inside the current stage and never certifies a partial layer.

Write the message about what the production now establishes, changes, or repairs, not the mechanical edit. State a downstream consequence when the change has one, so the log remains usable as production history.

Never create an empty or partial commit, stage broadly, mix files you do not own, move part of a layer to the next stage, enter review with unresolved evidence diagnostics, or begin a downstream layer while a required build fails.

Before committing text outside ASCII, decode every staged file as strict UTF-8 and reject a replacement character. Valid decoding alone cannot detect a substituted accent, curly quote, or unrelated-script letter, so also inspect the staged writing systems and reject a character that does not belong to the production's language. Encoding damage often raises no build error.
