# Contract targets

`docs/discovery` defines open production-specific searches, `docs/upstream` records what each inheriting unit learned by testing its actual parents, `docs/principles` defines the no-exclusion checklist every selected authored H2, H3, or H4 answers for itself, and `docs/obligations` defines roles covered one or more times across a layer's H2 owner population or a source layer's selected export population. Those four directories are this generated project's exact scaffold-owned contract inventory. This production keeps every additional rule it adopts for itself as one flat file directly under `docs/contracts`; the graph refuses a nested contract, an unwired local target, an enabled local target reference with an empty population, a host-side evidence tag inside a target H2, and an H2 title or anchor duplicated anywhere in the shared-plus-local target inventory.

The production design record is compiler-owned JSON, not an evidence-document host. A reviewed settings, research, or design H2 owns each delivery, repaint, dialogue, or simulation decision, the governed source that `scripts/emitDesign.ts` reads is where that decision is written, and `scripts/productionConfiguration.ts` refuses runtime drift, hidden fields, and inconsistent compiled consumers in the emitted record. Do not move ownership into a JSDoc beside the emitted field or add a design record to a Markdown claim population.

## Shared form

Use one H1, brief scope prose, and one fixed-anchor H2 per independently falsifiable target. Add no deeper heading. Each H2 states its falsifiable search or binding decision and boundary, one exact review question, and a final `Sources:` line supported by scholarship, standards, primary documentation, or established practice.

One target owns one concern. Conditional manifestations may stay together only when they test the same decision. Split a second target that can be applied, refuted, changed, repaired, cited, omitted, or reviewed independently. If the same host reason necessarily answers two sibling targets, merge them or state the boundary that makes their answers distinct.

Reusable targets must be independent of one production's subject, genre, characters, ending, assets, and implementation. A candidate without that generality stays under `docs/contracts` or in `.wiki`. A target states observable success, representative failure, and the upstream repair required when failure reveals an earlier owner. It does not prescribe a fixed count unless the underlying contract requires one.

## Discovery

Each discovery H2 owns an open search whose result cannot be enumerated before reading the production. Its host is the production-specific contract population `docs/contracts/*.md`, not an authored settings, research, design, narrative, or brief unit. A retained result is answered by the contract file that states the adopted rule. Asking an authored unit to testify about the contract lets a rule remain prose instead of becoming an enforced target.

The graph creates one discovery claim for each of the 13 authored Markdown populations: settings, research, maps, models, spaces, materials, instances, motions, systems, treatments, scripts, screenplays, and briefs. Every active population uses the same flat contract host, while its reference set remains population-specific: settings answers common plus settings; research answers common only; each design branch answers common plus designs plus its own branch; treatments, scripts, and screenplays answer common plus films plus their own layer; and briefs answer common plus briefs. Film activates settings, treatments, scripts, and screenplays; brief activates settings and briefs; library activates settings without a timed population. Each shape may additionally activate research and whichever of the seven design branches it actually needs. A shape-forbidden or disabled population keeps its discovery claim disabled. Source populations do not become discovery hosts.

One production declares one adopted rule once. The same contract file may answer the discovery claims of every population to which the rule applies, while one additive claim selects the authored H2/H3/H4 or source symbols that must obey or realize that rule. Merely mentioning the result in an authored host or adding a contract file without its enforcing additive claim does not adopt it.

A completed search that finds no independent rule is the one negative case. Record its population-wide `@evidenceExclude` before the H1 of `docs/contracts/index.md`, naming the concrete inputs and risks examined and the sufficient shared owners. `index.md` carries truthful negatives and nothing else: no adopted rule, target H2, positive discovery answer, or catch-all prose. Every discovery claim restricts exclusions to that file, so all omitted work-specific duties can be read in one place. Deferred work, an audit assertion, a label, or an empty directory is not a no-result.

Keep `docs/contracts` flat. Filenames own the family and scope, such as `principles-common.md`, `principles-narratives.md`, `principles-models.md`, `obligations-common.md`, `obligations-spaces.md`, or a descriptive independent name. A nested directory is selected by no `contracts/*.md` claim and is refused rather than silently ignored.

The scaffold ships this directory empty except for its tracker. Never seed `index.md`, a rule, an example, or a default from the template. A rule inherited by every generated production is shared by definition and belongs in the published shared inventory; the scaffold owes only the empty place and these instructions. Create `index.md` during the production's own audit only when a truthful negative is needed.

## Upstream revision

Each `docs/upstream` file contains one H2 checklist item for one inheriting population. Every selected design, brief, narrative H2/H3/H4, and source export answers its population's item about itself and its actual parents. Settings and research select no upstream target because they do not inherit an authored production unit. One host cannot answer for siblings: this family records a unit-to-parent examination, not population-wide coverage.

A positive answer names the exact parent defect exposed while authoring this unit and the repair made at the earliest owning parent before the result was propagated downward. A negative answer uses `@evidenceExclude` to name the exact parent facts and decisions examined and why they were sufficient for this unit. "No change needed", an audit assertion, or one sentence repeated across hosts is not an examination. Exclusion is essential here: without a truthful negative, every sound parent would force its child to invent a defect.

Never supply a missing capability, limit, participant, refusal, interface, dimension, or acceptance condition locally. Return it to its owner, repair that parent, and then resume the child. The child's upstream answer records the discovery and repair; it does not become the place where the parent decision lives. A parentless host is refused rather than given a fabricated upstream answer.

Upstream revision is distinct from parent differentiation. Upstream asks what authoring the child revealed about the adequacy of its parents and permits a concrete negative answer when they were sufficient. Parent differentiation asks what layer-owned decision the child itself added beyond those parents and permits no exclusion. A unit may therefore repair an upstream defect yet still fail to realize its own layer, or add valid local work while exposing no parent defect.

After finishing one inheriting unit, read its actual parent units and answer the population's single upstream question before continuing downstream. If the answer changes a parent, invalidate and reread every affected descendant. Do not divide one population into several upstream targets by defect kind: one answer reports every parent defect found during that unit's examination.

## Principles

Each `##` principle owns one semantic concern. Its title names the concern, its body states the binding rule, and its review question asks what the current unit must inspect about itself. Principle references are checklists: every selected authored H2, H3, or H4, and every selected source symbol when a claim governs source, answers every applicable `##`; exclusions are refused. A host that cannot truthfully claim compliance is defective. State an item's applicability limits inside that item rather than turning a missing answer into an exclusion.

Before adding or editing a principle, run the non-overlap test against every sibling in its family:

1. Write the candidate's subject in one noun phrase and its required decision in one verb phrase.
2. Do the same for each existing sibling.
3. If two pairs can govern the same decision, merge them or redraw the boundary before writing either.
4. Try one compliant example and one counterexample at the boundary.
5. Check that obeying one rule cannot violate another without an independently named concern explaining the tension.

Split by governed decision, not by writing convenience. Common principles contain only unit-level rules shared by every authored layer. Model principles govern deterministic representation; motion principles govern state over time; narrative principles govern audience-facing causality. Source realization and observation roles are obligations distributed across their selected export populations. A statement that mixes those domains belongs in the more specific family or must be decomposed.

## Obligations

Every obligation file is ordinary no-exclusion coverage. An authored-layer obligation assigns a role across one complete layer's H2 owner population; a source obligation assigns a role across one complete selected export population. An item no host cites is missing coverage. Several hosts may cite the same item wherever the item calls for several owners, such as one owner for each consequential subject or each source role. The same common or narrative obligation is answered again in every layer that selects it because each layer owes that role in its own terms.

Add a duty to `obligations` only when no single unit could answer it alone: it judges a file as a whole, the shape of a population, or a position only one or several units in the layer can occupy. A duty every unit must satisfy separately belongs in `principles`; putting it in obligations would let one owner answer for the entire layer.

Never duplicate a principle as an obligation. If each selected host must answer it about itself, it is a principle. If the population must collectively allocate it one or more times, it is an obligation.

A principle reported as unanswered means the current unit never asked that question of itself, so repair that unit. An obligation reported as unanswered means the population has no owner for that duty. When several units claim an obligation, confirm that the target calls for several owners; otherwise decide which unit owns it.

## Sources

Every reusable H2 cites the sources that support its rule. A source does not replace the production's decision. Prefer specifications, primary documentation, scholarship, and established practice, and record product-specific decisions only in their production owner.

## Change and review

An anchor is a citation address. Renaming it rewrites every citing host, so choose it for the durable question the target asks rather than its current wording. When an anchor must change, update every production, fixture, claim, acknowledgement, exclusion, and instruction link that cites it in the same coherent change.

Editing a target expires every review of that target. Reread the changed item against every governed host before renewing its review; do not replace only the fingerprint.

Inspect every changed contract literally with its linked skill callers and TypeScript population behavior. Check unique ownership, one-target scope, stable anchors, `Sources:` lines, local links, population semantics, and the absence of contradictory or duplicated completion points. After corrections stop, perform complete review rounds over the full instruction and contract diff. A round counts only when it finds no issue and causes no edit; require two consecutive counted rounds before final repository gates.
