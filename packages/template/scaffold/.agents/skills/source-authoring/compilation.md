# Compilation

The production compiler is an atomic fence with an ordered scope ladder. Each scope includes every check from the preceding scope. Invoke it through the scaffold compile command or `compileAutoMovieProduction`.

- `design`: validate manifest, design shape, ranges, identity, and references without reading source or materializing derived files.
- `source`: additionally materialize primitive models and compact formation runtimes; bind each `defineShot` registration to its design contract; execute its thin stage/block/performance program through the host engine pipeline; validate actor/object/formation motion, bounded fixed-step effects, scenes, and shots; derive contract realizations; and enforce generated ownership.
- `review`: additionally require every review in the derived queue to be complete and fresh.
- `final`: additionally require a current aggregate render manifest and matching byte/media receipt. The ledger is mandatory even when every listed deliverable is optional; `required` controls which declared ids must be present, not whether final delivery needs provenance.

What a review owes is derived from the current graph, never from a second branch table. At `review` and `final` scope the compiler asks whether the evidence exists. In a film or brief, a shot must hold every frame-and-pass pair its own contract's `reviewFrames` declare, and every model the compile actually consumed must hold the turntable set an asset review is judged from. Both are read at the target's current render-target fingerprint, so a frame drawn before that target last moved is on disk and does not count.

In a library there is no shot, so the source scope runs your design branches directly. Every file a reviewed source binding selects is linked, inspected, transpiled and evaluated in the same deterministic sandbox a shot's module runs in. What the compiler looks for in it is a named export carrying `design`, the exact `docs/<branch>/<document>.md#<anchor>` address of the reviewed H2 it realizes, and `build(context)`, which returns `{ environments, models, contexts }`. The graph-selected source path/export/digest/target edge is checked before `build` runs; `source-owner-mismatch` is an admission failure, not a registration warning. A maps owner must return at least one context and no environment or model, a models owner at least one model and no context or environment, and a spaces owner at least one environment and no context or model. Material, instance, motion, and system sources have no standalone result carrier yet and remain in authoring rather than completing through a nested payload. `contexts` stays optional at the DTO boundary for older source, but omission cannot complete a map owner. A module may export several owners and a module may export none, which is what a helper the owners import looks like; what it may not do is register an address the authoring declaration does not own, register an address a second export already registered, or publish an artifact id another owner already published. Each of those is refused at its own address, and a reviewed H2 that no export realizes warns while you are writing source and blocks from review on.

What comes back is published as compiler-owned bytes: each building under `generated/<production>/library/environments/`, each adopted world under `generated/<production>/library/contexts/`, each model under `generated/<production>/models/` where a film's models also land, and an index beside them naming the branch, owner, source file, export and source digest each artifact came from. The buildings and worlds in that index are what `readAutoMovieLibraryReviewRequirements` derives your required observation population from, and it derives them per owner: what you owe comes from what you yourself contributed, never from what the production happens to carry. The production design's own `environmentContext` belongs to nobody and charges nobody, which is why a map owner adopts its world here instead. A map owner that publishes no context is refused at review; every other branch derives only from the payload it actually publishes and remains accountable to its own finite plan. Generated ownership works exactly as it does for a film: an unchanged compile rewrites no file, a lint verifies the same expected bytes without writing, and a hand-edited generated file is refused by name.

In a library, the same compiler consumes the one typed authoring snapshot used by graph lint. Every active reviewed design/source branch contributes its exact design documents and H2 owners, including an exact empty population. Each H2's adjacent version-1 review plan names a finite domain observation set and source subset; each receipt binds the H2 digest, selected source bytes, compile fingerprint, plan digest, evidence bytes or structured facts, observation runtime, and verdict. `readAutoMovieLibraryReviewRequirements` exposes those current identities to production-owned offline observation commands without maintaining a map/model/space/material/instance/motion/system list. Missing or stale evidence comes back as `review-evidence-missing` at the exact branch, owner, or observation address. A library remains shot-free and never stages a dummy film to satisfy this gate.

The compiler stops there on purpose. Whether the frames are any good is settled by opening them and written into the evidence citation on the source that claims the unit is realized; no diagnostic decides that and no ledger records it.

The review scopes also add a check with no `source` form at all. An active screenplay scene that no required acceptance scenario cites is refused at `review` and `final` as `screenplay-scene-unobserved`, and is not reported at `source` in any category, because a compiled realization proves the film covers the scene while only a required acceptance scenario proves somebody looked at it. Read [Contract targets](../evidence-graph/contract-targets.md) for the citation that discharges it.

Any error returns `success:false` and materializes nothing. Warnings are explicit but do not block. Diagnostics name a stable code, phase, target, owning path, and exact correction.

Severity belongs to the invocation, not to the code. A diagnostic warns where the current gate cannot yet require the fact and errors where it can, so the same code changes category as you climb. `screenplay-scene-unrealized` and `film-runtime-mismatch` warn at `source`, where an unfinished film is the expected state, and block at `review` and `final`, where it is not. The `generated-*` ownership codes warn during a compile that is about to rewrite the tree anyway and block during a read-only lint, which reports the same disagreement and is deliberately unable to repair it. Read the category on the diagnostic you were actually returned; a severity remembered from another scope is not a fact about this one.

Source output never self-certifies the contract. The compiler measures named-state predicates at the opening and closing times, event predicates at source-selected samples inside authoritative windows, camera subjects at review frames, compact formation count/chunk/bounds/hero invariants, and the exact one-to-one binding between bounded effect cues and compiler-owned streams. Passing realizations are written under `generated/<production>/realizations`; failure blocks every generated write.

Every scope above `design` opens the derived-artifact ledger first, in the `project` phase, before a single source module is linked. A ledger the project manifest selects must sit at its canonical path, read as intact JSON, and still be current: each record's generator and declared inputs must hash to the recorded basis, the resident output bytes must match their recorded digest and decode under the declared encoding, and the derived namespace must not also be claimed by the external asset ledger. Each of those failures is an error under its own `derived-artifact-*` code, and each stops the compile before source runs, because compilation never invokes a generator and never repairs a stale result. Read this document for the ledger and the explicit generation command.

The input fingerprint includes compiler identity and protocol, ordered design, normalized source bytes, declared assets, and the derived-artifact ledger with each record's generator source, declared inputs, and output bytes. A derived path it could not read joins the fingerprint as absent-or-unsafe rather than being skipped, so deleting a file the gate refused does not make the compile current. The fingerprint excludes generated, review, and render bytes. Unchanged input produces the same fingerprint and generated bytes; an unchanged compile must not churn file mtimes.

The final scope trusts neither manifest labels nor old hashes. The renderer-owned aggregate receipt must match the current render manifest and every current file byte. AutoMovie decodes PNG and WebVTT output and parses MP4 tracks again to verify raster, frame count, frame rate, runtime, codec, channels, and sample rate as applicable. Caption readability produces a verdict only when the production selected a versioned profile; without one, compilation preserves measurements and a `not-run` reason instead of applying hidden default thresholds. Read `AUTOMOVIE_CAPTION_GRAPHEME_SEGMENTATION` from the package API before selecting the installed algorithm and Unicode/ICU revision. A different requested segmentation stays `not-run` as unsupported and is never evaluated through a fallback.

Use the narrowest scope that answers the current question. Exploration should not fake review completion, and final delivery should not bypass it.

## A clean compile is not a look

Compilation proves that the records agree with each other. It proves nothing about what the production looks like, and every defect that survived a full production survived a clean compile first.

A clean source compile is the precondition for evidence, not a substitute for it: `npm run turntable` and `npm run preview` refuse against a stale compile, and the compiler reports evidence as missing until the frames exist. Compile, then look, then record the verdict.
