# Common obligations

Duties each selected authored-layer population satisfies in that layer's own terms. An item no unit cites is missing coverage; several units cite an item wherever its wording calls for several owners. No obligation is a checklist, and none permits exclusion.

## Purpose fit {#purpose-fit}

Each authored file performs one or more roles needed by the production promise and the scope of the current delivery. Connect material that does not contribute to those roles with another element or remove it.

Judge this by what the file population actually includes and omits. The author must be able to explain how those choices serve the production promise.

Review question: which file roles does this population need, and what later decision or delivered observation would become underdetermined if each role disappeared?

This item asks why a file as a whole is needed. Specialist addressability obligations govern independent ownership by authored units, the common scope-preservation principle governs each unit's required scope, and narrative unit function governs the need for an individual narrative unit.

Sources: [Jakobson on the dominant that orders the functions of other elements](https://archive.org/details/readingsinrussia0000mate); [Burton and Poster on the distinct work done by beginnings, endings, tension, and pace](https://www.cambridge.org/core/books/abs/book-you-need-to-read-to-write-the-book-you-want-to-write/beginnings-and-endings-tension-and-pace/7B84CB546C696FD1B6A8AB753522B42C)

## Layer boundary {#layer-boundary}

Each authored file declares one document role and contains only decisions recognized by that role's specialist principle or obligation family. A mixed-role file is split, and a missing decision begins in the layer whose contracts own it before being carried downward. This common obligation owns routing and single-role composition; the specialist contracts define the content of each role.

Review question: which decision in each file requires a second specialist family to justify it, and where must that decision move?

This item asks which layer owns a decision. The common substantive-completion principle asks whether each addressed unit is complete at that layer.

Sources: [Plan-and-Write on separating planning from realization](https://doi.org/10.1609/aaai.v33i01.33017378); [Detailed Outline Control on controlling generation through an explicit intermediate plan](https://arxiv.org/abs/2212.10077)

## Production language {#production-language}

The authored population uses the primary working language declared in settings with enough grammatical and terminological consistency for its intended readers. Exact identifiers, source titles, quotations, established technical terms, and deliberately authored multilingual content may retain another language when their function and audience access remain explicit.

Review question: can the intended reader understand every production decision across the population without guessing across inconsistent language, unexplained terminology, or an unowned language switch?

This item owns the linguistic accessibility of the authored population. Settings owns which working and audience-facing languages the production selected, while screenplay and film source own the content and timing of dialogue, captions, and audible language.

Sources: [W3C Internationalization on declaring language in HTML](https://www.w3.org/International/questions/qa-html-language-declarations); [BBC screenplay format and language presentation](https://downloads.bbc.co.uk/writersroom/scripts/screenplay.pdf); [W3C Timed Text Markup Language](https://www.w3.org/TR/ttml2/)

## Proportionate development {#proportionate-development}

Across the complete selected population, unit count and granularity, authored body within each unit, and internal progression are proportionate to the declared production scale and to the importance of represented subjects, transitions, narrative turns, observations, and implementation decisions. Major work is not compressed into a few umbrella units or short reports, and minor work is not inflated to imitate completeness. Compare siblings and assign greater concrete development and consequence to the material whose production effect is greater.

For the narrative ladder, record every complete layer body excluding comments. Treatments establish the flat event baseline. Compare the script population with that baseline in whole and use their many-to-many evidence edges to read the units that realize each treatment event. Scripts and screenplays share the delivery partition, so compare each group and unit as well as both populations in whole. A downstream narrative layer whose authored body does not exceed its parent's has restated that parent or dropped work its layer owes. When the production's chosen form genuinely requires the opposite, settings states the reason instead of leaving the comparison unmade. Settings inherits no authored layer and answers from its own population.

A brief performs the same audit inside its delivery, shot, and observation hierarchy: record the H2/H3/H4 population and authored-body distribution, then read whether each depth adds the bounded staging or falsifying observation its parent leaves to it. Do not demand that one concise observation be longer than the shot it tests; the comparison detects a collapsed hierarchy, while the literal question decides whether the observation is sufficient.

Do not compare prose length across design -> source. Source is TypeScript, so character count against a design document proves nothing. At that boundary, compare whether every selected design H2 is realized and whether consequential design decisions receive proportionate implementation depth. Library asset count, spatial level or zone count, representation variation, source-owner distribution, and required neutral observations are scale signals in their own terms.

When the user specifies runtime, delivery-group or episode count, shot budget, asset count, building extent, life span, historical interval, or another production scale, that scale governs every layer in the form the layer can answer. A layer carrying a delivery partition answers with that partition and its allocation. A layer without one answers whether its material can sustain the declared scale and whether it would overrun it. That is the earliest place either failure is visible and the last place it is cheap to repair.

When rewriting the same scope, the earlier version's group directories, unit files, selected H2/H3/H4 counts, authored body excluding comments, distribution by unit, asset and source-owner counts, required observation population, and research breadth are regression alarms. Counts do not prove quality, but a result in which several measures collapse together without an approved scope change is not complete.

Structure and amount detect a regression; literal reading judges whether the material is actually sufficient. A longer layer can merely expand a parent's wording. The narrative parent-differentiation principle and each layer's authoring gate decide whether the added body contains decisions owned by that layer.

This obligation asks only about quantity and allocation across the population. The scope-preservation principle asks whether required content exists, the substantive-completion principle asks whether each addressed unit is a real layer deliverable, and specialist addressability obligations ask whether the population chose truthful unit boundaries.

Review question: what do the recorded sibling, parent-layer, declared-scale, and earlier-version comparisons expose as compressed below its consequence or expanded without production work, and what does a literal read of the complete population decide?

When this obligation fails, redesign the complete selected population and its unit boundaries, expand consequential units, and split overloaded owners before advancing the layer. Stop downstream authorship until the earliest disproportionate layer is repaired. Do not thin units into summaries merely to retain an unworkable count.
