# Shot Contract

A tracked shot contract says what a shot must accomplish and which source export implements it. It never stores dense keyframes or an action list.

Bind one project-relative TypeScript module and named export. Declare duration, participants, opening and closing named states, camera readability, semantic events, and review frames. Duration must equal an integer production frame count divided by fps; event windows and review times must lie inside it. Formation participants must reference current formation designs.

Every named opening state, closing state, and event needs at least one machine-checkable predicate. Use joint-angle, world-position, or distance predicates with explicit operands, comparison, value, and tolerance. Descriptive prose gives creative meaning but never proves realization.

The coding agent exports `defineShot(id, { scene, contract, build })` from `src`. The build may use loops, source-local helpers, explicit design seeds, compiler-provided `runtimeModels` and compact `formationRuntime`, and `context.engine` oracles. It returns actor runtime facts plus a typed script, stage, blocking, performance, and one `eventSamples` entry per declared event; an explicit `enact` may cite a source-computed clip, while ordinary verbs stay thin and host-synthesized. The production host runs stage → block → perform, ROM/artifact gates, continuity sampling, and independent contract realization. Optional bounded `formationMotions` and `effectCues` remain compact production inputs. Do not return a finished scene, shot, model inventory, anonymous formation nodes, particle arrays, arbitrary effect programs, per-member curves, or a compliance witness: the compiler owns and measures those facts.

IDs, duration, camera, motion references, model wiring, ROM, predicate outcomes, and temporal rules are engine-validated. The compiler samples opening predicates at zero, closing predicates at shot duration, event predicates at declared samples, and required camera subjects at review times. A failed measurement blocks compilation even when source prose claims success.

Camera validation clips each required subject's vertical extent, from its animated root through its measured height, against the current camera frustum, FOV, clip planes, and production aspect ratio. A subject reads when any part of that extent falls inside the frame, so a deliberately cropped shot size still passes: a `close` frame shows roughly the band between 0.71 and 0.99 of the subject's height, which contains neither the subject's feet nor the top of its head. Every shot size is therefore available to a shot that declares its subjects. Validation still does not measure `maxOcclusionRatio`, full-body framing, or pixel visibility. Treat that value as the maximum allowed pixel-occlusion threshold, inspect current beauty, mask, depth, outline, or pose PNGs, and cite the exact required frames through `submitReview`.

Every shot declares at least one review frame so visual review has a reachable exact evidence target. Review frames are deliberate evidence points: contact, reveal, formation transition, or a continuity boundary. Request the guide passes needed to judge the criterion; beauty alone cannot prove depth, masking, pose, or outline facts.
