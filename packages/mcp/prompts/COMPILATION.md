# Compilation

`compileProject` is an atomic fence with four scopes.

- `design`: validate manifest, design shape, ranges, identity, and references; materialize only design contracts.
- `source`: additionally bind and execute shot source, validate models, scenes, motions, and shots, and enforce generated ownership.
- `review`: additionally require every current design, source, shot, and film review to be complete and fresh.
- `final`: additionally require current render and delivery manifests.

Any error returns `success:false` and materializes nothing. Warnings are explicit but do not block. Diagnostics name a stable code, phase, target, owning path, and exact correction.

The input fingerprint includes compiler identity, ordered design, normalized source bytes, and declared assets. It excludes generated, review, and render bytes. Unchanged input produces the same fingerprint and generated bytes; an unchanged compile must not churn file mtimes.

Use the narrowest scope that answers the current question. Exploration should not fake review completion, and final delivery should not bypass it.
