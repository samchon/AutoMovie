# Principles and obligations

`config/docs/principles` defines what every governed host must answer. `config/docs/obligations` defines how a population divides responsibility. They are different contracts.

## Principles

Each `##` principle owns one semantic concern. Its title names the concern, its body states the binding rule, and its review question says exactly what a reviewer must inspect. Authored-document principle references are checklists: every governed Markdown file answers every applicable `##`, and exclusions are refused. Source principles are instead covered across their selected export population because a constructor, reusable motion, delivery, and acceptance record have different applicable duties; every source H2 still needs concrete implementation evidence, and the separate exact design edge prevents an exported owner from becoming undocumented or multiply owned.

Before adding or editing a principle, run the non-overlap test against every sibling in its family:

1. Write the candidate's subject in one noun phrase and its required decision in one verb phrase.
2. Do the same for each existing sibling.
3. If two pairs can govern the same decision, merge them or redraw the boundary before writing either.
4. Try one compliant example and one counterexample at the boundary.
5. Check that obeying one rule cannot violate another without an independently named concern explaining the tension.

Split by governed decision, not by writing convenience. Common principles contain only rules shared by every production document. Model principles govern deterministic representation; motion principles govern state over time; narrative principles govern audience-facing causality; shot principles govern realization and observation. A statement that mixes those domains belongs in the more specific family or must be decomposed.

## Obligations

An obligation assigns distinct facts or decisions across a whole population. Coverage is distributed: each obligation unit must be answered somewhere, but every file need not cite every unit. An obligation may permit one population-wide exclusion only when the entire production truly lacks that concern.

Never duplicate a principle as an obligation. If every host must obey it, it is a principle. If the population must collectively allocate it, it is an obligation.

## Sources

Reusable contracts cite authoritative sources where the rule depends on an external technical fact. A source supports the rule; it does not replace the production's decision. Prefer specifications and primary documentation, and record product-specific decisions directly.
