# Principles and obligations

`config/docs/principles` defines what every governed file must answer. `config/docs/obligations/common.md` defines what every selected authored unit must answer, while the other obligation files define how a population divides required roles. Production-local targets follow the same forms under `docs` and activate only through additive claims.

## Shared form

Use one H1, brief scope prose, and one fixed-anchor H2 per independently falsifiable target. Add no deeper heading. Each H2 states the binding decision and boundary, one exact review question, and a final `Sources:` line supported by scholarship, standards, primary documentation, or established practice.

One target owns one concern. Conditional manifestations may stay together only when they test the same decision. Split a second target that can be applied, refuted, changed, repaired, cited, omitted, or reviewed independently. If the same host reason necessarily answers two sibling targets, merge them or state the boundary that makes their answers distinct.

Reusable targets must be independent of one production's subject, genre, characters, ending, assets, and implementation. A candidate without that generality stays production-local or in `.wiki`. A target states observable success, representative failure, and the upstream repair required when failure reveals an earlier owner. It does not prescribe a fixed count unless the underlying contract requires one.

## Principles

Each `##` principle owns one semantic concern. Its title names the concern, its body states the binding rule, and its review question says exactly what a reviewer must inspect. Authored-document principle references are checklists: every governed Markdown file answers every applicable `##`, and exclusions are refused. Source principles are instead covered across their selected export population because a constructor, reusable motion, delivery, and acceptance record have different applicable duties; every source H2 still needs concrete implementation evidence, and the separate exact design edge prevents an exported owner from becoming undocumented or multiply owned.

Before adding or editing a principle, run the non-overlap test against every sibling in its family:

1. Write the candidate's subject in one noun phrase and its required decision in one verb phrase.
2. Do the same for each existing sibling.
3. If two pairs can govern the same decision, merge them or redraw the boundary before writing either.
4. Try one compliant example and one counterexample at the boundary.
5. Check that obeying one rule cannot violate another without an independently named concern explaining the tension.

Split by governed decision, not by writing convenience. Common principles contain only rules shared by every production document. Model principles govern deterministic representation; motion principles govern state over time; narrative principles govern audience-facing causality; shot principles govern realization and observation. A statement that mixes those domains belongs in the more specific family or must be decomposed.

## Obligations

`obligations/common.md` is not distributed coverage. It is a no-exclusion checklist that every selected settings, model, and motion H2 and every film or brief H2/H3/H4 answers directly. Each item owns a unit-level completion or evidence-integrity duty whose explicit failure and halt rule must survive agent summarization. Do not duplicate a file-level craft principle there.

A layer obligation assigns a distinct fact or decision across a whole H2 population. Coverage is distributed: each target must be answered somewhere, but every file does not repeat every role. Settings, model, and storyline roles are required and permit no exclusion. A motion role may permit one population-wide exclusion only when the complete production truly lacks the condition named by that target.

Never duplicate a principle as an obligation. If every host must obey it, it is a principle. If the population must collectively allocate it, it is an obligation.

## Sources

Every reusable H2 cites the sources that support its rule. A source does not replace the production's decision. Prefer specifications, primary documentation, scholarship, and established practice, and record product-specific decisions only in their production owner.

## Change and review

Editing a target expires every review of that target. Reread the changed item against every governed host before renewing its review; do not replace only the fingerprint.

Inspect every changed contract literally with its linked skill callers and TypeScript population behavior. Check unique ownership, one-target scope, stable anchors, `Sources:` lines, local links, population semantics, and the absence of contradictory or duplicated completion points. After corrections stop, perform complete review rounds over the full instruction and contract diff. A round counts only when it finds no issue and causes no edit; require two consecutive counted rounds before final repository gates.
