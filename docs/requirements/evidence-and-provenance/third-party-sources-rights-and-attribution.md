# 서드파티 출처, 권리와 귀속

## 채택한 서드파티 source의 기록 {#third-party-source-record}

외부 model, motion, image, audio, font, text, dataset, software output와 reference를 작품에 채택하면 source 위치 또는 제공자, creator나 publisher가 알려진 경우 그 identity, 취득 시점, 고정된 bytes 또는 snapshot, digest와 채택한 consumer를 기록해야 한다.

### 권리와 사용 조건 {#third-party-rights-and-terms}

License, permission, terms version, attribution 의무, 허용 용도, 지역과 기간 제한, 수정과 재배포 조건을 source와 연결하고, 권리를 알 수 없거나 증빙할 수 없는 경우 그 상태를 명시해 승인된 사용으로 표시하지 않아야 한다.

### 귀속의 전달 {#third-party-attribution-propagation}

필수 attribution, notice와 license copy는 변환, 합성, render, 전달 묶음과 publication을 거쳐 필요한 전달물까지 이어져야 하며, 여러 source가 결합된 결과에서도 어느 의무가 어느 source에서 왔는지 사용자가 구분할 수 있어야 한다.

### Provider와 생성형 source {#third-party-generated-source}

외부 생성 service의 결과는 provider, model과 version, 요청과 reference, 적용 terms, 원시 결과와 채택 결과의 identity를 기록하고, service가 부여하지 않은 저작권, 독점성, training source의 청정성 또는 재현성을 제품이 대신 보증해서는 안 된다.

### Source 변경과 철회 {#third-party-source-change-and-withdrawal}

Remote source, license, permission, provider terms 또는 권리 주장이 변경, 만료, 철회되면 영향받은 asset, derivation, publication과 대체 필요성을 식별하고 기존 승인 상태를 자동으로 유지해서는 안 된다.

### 원본 접근 제한 {#third-party-source-access-restriction}

계약이나 privacy 때문에 원본 bytes를 배포할 수 없으면 사용자는 제한 사유, 보유 위치 또는 책임 주체, 검증 가능한 identity와 허용된 검토 방법을 확인할 수 있어야 하며, 접근 불가를 source가 존재하지 않는다는 뜻으로 바꾸거나 검증 완료로 표시해서는 안 된다.
