# Continuity, 변경과 산출물

## 같은 Design에서 파생되는 Production {#production-design-continuity-deliverables}

Subject specification, model, location, dressing, state, shot, schedule, drawing, quantity, render와 review는 같은 design revision과 identity를 참조해야 한다.

Derived artifact는 source design을 복사한 두 번째 정본이 아니라 projection이어야 하며 자신이 읽은 revision, variant, phase, tool 또는 process와 settings identity를 표시해야 한다.

### Continuity Ledger {#production-design-continuity-ledger}

Costume, prop, damage, dirt, opening, furniture, weather, light와 crowd state를 scene와 story time에 따라 추적하고 edit 순서만으로 상태를 결정하지 않아야 한다.

Ledger는 state의 적용 subject 또는 location, 시작과 종료, 원인 event, 이전과 다음 state, source authority와 evidence를 가질 수 있어야 한다. 같은 subject의 mutually exclusive state가 같은 story moment에 current로 남지 않아야 한다.

### 변경 영향 {#production-design-change-impact}

Art direction, scale, location, subject, material, tier와 budget 변경이 affected scene, asset, shot, sound, edit, render와 evidence에 미치는 영향을 식별할 수 있어야 한다.

직접 참조뿐 아니라 shared prototype, instance, palette role, state schedule, route, reflection, shadow, sound context와 derived quantity를 consequence surface에 포함해야 한다. 한 render가 겉으로 비슷하다는 이유로 다른 deliverable을 current라고 유지하지 않아야 한다.

### Breakdown 산출물 {#production-design-breakdown-deliverables}

Location list, character·prop·set list, asset plan, palette, material board, state schedule, budget와 unresolved decision을 동일한 source identity에서 산출할 수 있어야 한다.

각 산출물은 목적, consumer, required 또는 optional 상태, format 또는 human-readable view, completeness rule와 acceptance를 가질 수 있어야 한다. Category에 항목이 없을 때 true empty, excluded와 not-run을 구분해야 한다.

### Freshness {#production-design-deliverable-freshness}

Source 변경 뒤 stale drawing, render, capture와 review receipt를 current로 제시하지 않고 재생성 또는 명시적 not-run 상태를 요구해야 한다.

### Design Bible과 Decision Register {#production-design-bible-decisions}

Project는 current art direction, location, subject, scale, palette, material, state, tier, reference와 unresolved decision을 하나의 navigable inventory로 열어 볼 수 있어야 한다. 이 view는 각 owning source로 연결되어야 하며 별도 prose copy로 drift하지 않아야 한다.

### Change Set와 비교 {#production-design-change-set-comparison}

두 revision, variant 또는 phase 사이에서 added, removed, replaced, changed와 unchanged design identity를 비교하고 semantic consequence와 derived artifact freshness를 볼 수 있어야 한다. Byte diff만으로 scale, state와 source authority 변경의 의미를 판단하지 않아야 한다.

### Deliverable Source Authority {#production-design-deliverable-source-authority}

Drawing, schedule, quantity, asset bundle, capture와 render가 design source와 충돌하면 tracked design과 validated current derivation이 권위를 가져야 한다. Hand-edited derived artifact를 최신 design으로 역승격하지 않아야 한다.

### 누락과 부분 산출물 {#production-design-deliverable-gaps}

필수 대상, sheet, state, reference, budget metric 또는 review가 누락되거나 부분 생성되면 exact gap과 영향을 보고해야 한다. 일부 file이 생성됐다는 이유로 inventory 전체를 complete로 표시하지 않아야 한다.

### 산출물 Provenance와 Receipt {#production-design-deliverable-provenance}

각 distributable은 source revision, input assets, generation activity, tool 또는 renderer identity, parameters, output digest, media 또는 document facts와 publication state를 추적할 수 있어야 한다. Label과 output path만을 completion proof로 사용하지 않아야 한다.

### Final Design Handoff {#production-design-final-handoff}

최종 handoff는 승인된 design revision과 variant, required deliverable inventory, current artifacts, open risk, exclusions, license와 attribution obligation, acceptance와 reviewer decision을 함께 제공해야 한다. Stale, unsupported와 not-run 항목이 숨은 상태로 완료되지 않아야 한다.
